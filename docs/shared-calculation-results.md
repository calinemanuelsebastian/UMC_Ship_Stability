# Shared calculation results

The solver entry points now use `src/core/calculations/shared-results.ts`. This is an application-session service, independent of React mounting and display language/reference settings. Consumers still manage their own pending/error presentation, but share the same fulfilled result object and in-flight computation for identical requests.

- Loading totals are memoized by the immutable weights array, avoiding rescans on unrelated app renders.
- Upright hydrostatics, GZ curves and linear trim are cached by vessel/package revision, normalized condition and solver options. Optional zero attitude/FSM values normalize to explicit zero, allowing assessment panels and 3D to share a request.
- Parsed upright CSV, cross-curve CSV, constant-LCB curves, flooding data, trim tables, wind profiles and KG limits are reused independently of loading-condition changes. Frozen shared trim tables also retain up to 16 LCB-balance solutions, shared by the wind/trim assessments, initial trim for stability and the 3D trim view.
- The cache snapshots inputs and package metadata before asynchronous work; returned plain results are cloned and recursively frozen. Callers cannot modify another page's result or freeze the user's input object. In-flight tasks are deduplicated; one unmounted consumer does not cancel work needed by another.
- Each weakly owned vessel scope retains at most 32 settled entries, evicting least recently used entries. Pending requests remain until settlement to preserve deduplication. Neither calculations nor source tables are persisted to browser storage.
- Manifest, base URL and resource URL changes create a fresh scope. Distinct package objects never share results solely because they have the same vessel ID. `sharedResults.invalidate(ship)` explicitly refreshes a source replaced at the same URL without a package change. A browser reload also clears the session cache. Remote content changes at an unchanged URL are not polled.
- Rejections are removed so a later request can retry. Old requests can settle only their own condition/revision entry. App-level displacement resolution, Stability Curves, linear Trim and the 3D viewer additionally require matching vessel identity before displaying a local result. Existing pending guards and the shared 300 ms input delay remain in place.

No equations, coordinate conventions or source-coverage restrictions were changed. The layer does not supply missing heeled draught/trim data or turn the 3D animation into a time-dependent dynamics simulation.

Validation includes concurrent identical requests, default normalization, nested solver reuse, input snapshots, immutable results, vessel/version invalidation, retry after errors, out-of-order completion and bounded eviction. A production Vectis test confirms that three simultaneous GZ consumers share one result and three source fetches; changing KG recalculates GZ without fetching those source tables again. Existing numerical reference tests are retained. Tests that replace fixture files at an unchanged URL now explicitly invalidate that source rather than accidentally receiving a correctly cached previous fixture.
