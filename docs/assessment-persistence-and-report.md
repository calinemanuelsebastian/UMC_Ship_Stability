# Step 6: reproducible assessment workflow

Assessment settings live in the Simulator's shared context, alongside loading inputs. The optional `ScenarioState.assessment` field is preserved by local Save condition, scenario JSON export/import, and cargo-plan save/export/import. Legacy version-1 records without this field remain supported. The parser retains editable settings only, bounds string lengths and rejects nonfinite values; imported calculation results are discarded.

Weather profile, LWL, CB, bilge area, deck/flood angles, symmetry option and source/assumption text persist across Stability Curves and 3D View. The manual moulded-draft fallback is also retained. Each settings group is tied to a canonical key of displacement, LCG, KG, TCG, transverse FSM, density and longitudinal FSM. A numerical condition change makes the old settings inactive and visibly requests new inputs. Original settings remain available in the saved snapshot. Restoring the same numerical condition reactivates matching settings. Changing wind profile creates fresh weather inputs (with the supplied bilge-area default). Clearing a field stays blank rather than falling back silently.

Open Condition settings → Export complete assessment report. JSON export captures an immutable click-time copy of all scenario inputs and settings, vessel manifest, current numerical inputs, source/limit datasets, results and unresolved checks. It computes sections independently: one unavailable solver or missing profile does not suppress the rest. It includes source-booklet fingerprints where available, trimmed tables, assessment basis, annotated KG and wind data used, and constant-LCB source ordinates for a computed Vectis curve. KG convention qualifications remain explicit. Cargo loads are unavailable for manual conditions rather than attached to unrelated cargo geometry.

Existing numerical functions and vessel-scoped caches are reused; report generation is on demand and does not run per animation frame. Returned results are freshly obtained for the snapshot. Reports are not imported as saved conditions or trusted as calculation inputs. The exported report schema has its own format/version. This release provides open JSON rather than a PDF presentation layer.

Tests cover settings round-trip, old records, malformed values, condition-key changes, input isolation during asynchronous export, missing/stale weather inputs and combined sections. Visual browser interaction testing remains outstanding.
