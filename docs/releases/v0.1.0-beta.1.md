# UMC Ship Stability v0.1.0-beta.1

First public demo prerelease. The website is already available at https://calinemanuelsebastian.github.io/UMC_Ship_Stability/.

## Included workflow

- Vectis Castle and Rectangular Pontoon model packages.
- Cargo layout, stacking/support tools, identification, ballast and liquid inputs, and linked weight totals.
- 3D inspection driven by shared numerical results, with teaching controls and transparency settings.
- Table-based hydrostatics, trim, stability/weather assessment, reference validation and theory.
- English/Romanian interface and reference-system selection.
- Named conditions, cargo-plan JSON import/export, undo on application, and full-condition recovery.

## Recovery corrections

Damaged saved records no longer hide valid plans. Tabs retain independent drafts; stale named-plan updates are rejected. Recovery preserves manual mode and assessment inputs. Each debounced checkpoint is journaled before joining the database queue, so pending edits remain recoverable when an older database write stalls.

In Brave, user-performed force-quit tests restored both a completed save and, after fixing an initial failure, the latest checkpoint while database writes were deliberately stalled in an isolated test copy. The latter restored 70 loading rows, density 1.012, longitudinal FSM 23, name and notes. The test instrumentation is not shipped.

## Demo walkthrough

1. Open the website, choose Vectis Castle in Condition settings, and select weight-based loading. If a recovery notice appears, restore it or keep the current condition intentionally.
2. In Loading, choose a documented starting condition and inspect ballast, tanks, and fixed weights. Note the starting displacement and centres.
3. Open Cargo layout, select a loading surface, place cargo, copy/rotate a selection, and inspect its properties. Add support/dunnage where appropriate and review any warnings.
4. Check Weights and totals, then 3D inspection. Confirm that the same condition is reflected in both and distinguish calculated attitude from imposed teaching angles.
5. Open Assessment and inspect numerical results, missing-data messages and criteria. Do not treat an unavailable result as a pass.
6. Save a named condition and cargo plan. Download JSON backups. Reload, review/apply recovery, then import a backup and demonstrate Undo application.
7. Open Validation to compare documented reference cases independently of the current loading condition.

## Scope and known limitations

This is an educational beta, not an approved operational loading instrument. Numerical assessment does not certify complete IMO compliance. Vessel geometry is reconstructed; table coverage, opening/downflooding data, tank assumptions and mode-specific limitations shown in the app still apply. Dunnage geometry is not a structural securing approval.

Storage is per browser and website origin. Export backups for transfer and before clearing browser data. Recovery cannot guarantee edits within the initial 250 ms debounce, browser quota/eviction, OS power loss or device failure. Safari/private-mode crash recovery was not verified. Imported plans reference model data; they do not embed entire vessel packages.

## Validation and distribution

This release candidate passed 392 automated tests, lint, TypeScript/production build and hosting-path checks. It includes the deployed recovery correction from commit 0c664d8.

The website ZIP uses the /UMC_Ship_Stability/ base path: serve its contents at that path over HTTP(S), not by opening index.html as a local file. Rebuild with `npm ci` and `npm run build -- --base /` for a root-hosted installation (Node 24). GitHub provides source archives with the release tag. Check SHA256SUMS before redistributing the prepared website ZIP.
