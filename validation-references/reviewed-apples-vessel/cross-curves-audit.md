# Vectis Castle cross-curve extraction

Source: `004_STABILITY_LOADING_MANUAL.pdf`, chapter 11, PDF pages 60–77 (printed 11.2–11.19). Conventions: PDF pages 6, 12–13 and 59. The JSON records the source SHA-256.

## Coverage and provenance

- Initial trims as printed: −2.000, −1.500, −1.000, −0.500, 0.000, +0.620 m.
- Displacement: 3,500–14,800 metric tonnes, at 100-tonne intervals.
- Starboard heel: 0, 2, 5, 10, 12, 15, 20, 25, 30, 35, 40, 50 and 60 degrees.
- 114 displacement rows per trim, 684 rows total, 8,892 ordinates.
- Each three-page set contains 55 + 55 + 4 rows. Page and printed-page references accompany every row.
- Original three-decimal source tokens, including `-0.000`, are retained in JSON and CSV. Values are not smoothed, corrected or extrapolated.
- The ordinate is printed as **KN sin(phi)**, in metres. It is already the cross-curve lever used in `GZ = ordinate − KG' sin(phi)`; do not multiply it again by sine. The worked example on PDF page 13 additionally shows the TCG cosine contribution.

## Verification and corrections

Every row and every numeric token matched independent pypdf and pdfplumber text extraction. Row lengths, unique displacement sequence, coverage and page headers were checked. Visual spot checks used PDF pages 60, 72 and 77; the explanatory page 12 was also inspected. No transcription corrections were needed. This does not certify that the original manual contains no errors.

For example, at initial trim −2 m and displacement 3,500 t, the 2-degree ordinate is 0.413 m and the 60-degree ordinate is 6.865 m. At initial trim +0.620 m and displacement 14,800 t, those ordinates are 0.270 m and 6.658 m.

## Solver constraints

**The manual explicitly modifies trim during heel to maintain constant LCB.** Initial trim 0 m does not mean fixed trim 0 degrees throughout heel. These files are therefore registered as documentation resources, not as the current `stability.cross-curves` solver input. The existing fixed-trim solver has not been enabled for Vectis by this extraction.

Only starboard inclinations are supplied. Port curves have not been generated by assumed symmetry. Mass ordinates have not been converted to volume using an assumed water density. A compatible solver must resolve these conventions before calculating heel and should be checked against the worked example on PDF pages 12–13.

Downflooding information printed after the last four rows of each set is excluded from the ordinate dataset. PDF page 59 states no unprotected progressive-flooding openings up to 40 degrees. The existence of 60-degree ordinates must not be interpreted as an operational limit; for example, page 77 also contains a finite downflooding displacement at 60 degrees for the starboard engine-room supply vent.

## Reproduce

Run `scripts/extract-vectis-cross-curves.py SOURCE_PDF OUTPUT_DIRECTORY` using a Python environment with pypdf and pdfplumber. The script fails on extraction disagreement or unexpected coverage. Keep this audit with the CSV/JSON and double-check subsequent stability calculations when the constant-LCB solver is implemented.

## Constant-LCB solver validation

The initial extraction-only status above is superseded by the dedicated `stability.constant-lcb-cross-curves` solver. The fixed-zero-trim solver remains separate. See `cross-curves-worked-example.json` for all 13 sample comparisons and source discrepancies.

The worked example uses 13,201.307 t, initial trim −0.774 m, corrected KG 4.647 m and starboard TCG 0.004 m. No additional FSM is applied to this already-corrected KG. Maximum ordinate difference is 0.000920 m; maximum GZ difference is 0.000773 m, both within the printed 0.001 m precision. The piecewise-linear GZ root is 0.076318° starboard, compared with the printed 0.074°. Page 14 explicitly describes small-angle sensitivity to rounded TCG/TCB.

Source-review findings: page 14 prints trim −0.792 m instead of the −0.774 m on pages 12–13, and labels an approximation as port despite the page-13 starboard result and positive starboard TCG. These statements are logged, not silently corrected in the source PDF. Double-check calculations relying on those example statements.

The application derives initial trim from shared LCG and the packaged trimmed hydrostatic table; the validation example instead prescribes its documented initial trim. Density is currently restricted to the configured 1.025 t/m³ seawater convention (manual conversion conventions, PDF p7). No density scaling is performed on extracted mass tables. Longitudinal FSM must be zero. Port curves, heeled draft/trim trajectories, downflooding and full stability criteria remain outside this calculation.
